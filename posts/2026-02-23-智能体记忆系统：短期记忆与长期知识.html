核心概念介绍

AI智能体的记忆系统是其能够持续学习、积累经验并与用户建立长期关系的核心组件。与人类记忆类似，智能体记忆也分为不同层次：

记忆类型 存储时长 容量 特点
工作记忆 单次对话 有限 当前上下文窗口内的信息
短期记忆 多轮对话 中等 会话期间保持的上下文
长期记忆 永久 大 跨会话的知识和经验

记忆 vs 知识库

  • 记忆：个人化的、动态的、与特定交互相关的信息
  • 知识库：静态的、通用的、预先定义的事实数据

为什么需要记忆系统

1. 解决上下文丢失问题

当对话过长或模型上下文窗口有限时，早期的信息会被"遗忘"。记忆系统可以：

  • 保存关键信息
  • 在需要时检索相关内容
  • 维护对话的连贯性

2. 实现个性化体验

记住用户的：

  • 偏好设置
  • 历史选择
  • 常用工作流
  • 个人背景信息

3. 支持持续学习

  • 从过去的交互中学习
  • 积累经验改进响应
  • 建立用户画像

记忆类型详解

1. 工作记忆（Working Memory）

当前会话窗口内的信息，由大语言模型原生支持。

限制：受模型上下文窗口限制（如 GPT-4 的 128k tokens）
特点：无需额外实现，但容量有限

2. 短期记忆（Short-term Memory）

跨会话但临时的信息存储，通常保存在内存或缓存中。

适用场景：

  • 当日日程安排
  • 临时任务列表
  • 会话摘要

3. 长期记忆（Long-term Memory）

持久化存储，通常使用向量数据库或文件系统。

实现方式：

  • 文件存储：Markdown、JSON 文件
  • 数据库存储：向量数据库（Pinecone、Chroma、Milvus）
  • 知识图谱：结构化的关系网络

OpenClaw 记忆管理实战

OpenClaw 提供了内置的记忆管理工具，让智能体能够轻松实现记忆功能。

文件结构

clawd/
├── memory/
│   ├── 2026-02-23.md          # 每日记忆日志
│   └── heartbeat-state.json   # 状态记录
├── MEMORY.md                   # 长期记忆库
├── SOUL.md                     # 智能体人格定义
└── USER.md                     # 用户信息

关键文件说明

1. MEMORY.md - 长期记忆库

存储需要长期保留的重要信息：

  • 用户偏好
  • 历史决策
  • 经验教训
  • 项目背景
# MEMORY.md 示例

## 用户偏好
- 喜欢简洁的回答
- 偏好使用 Python
- 工作时间：9:00-18:00

## 重要日期
- 2026-02-20: 启动了 Moltbook 集成
- 2026-02-22: 完成了 RSS 技能开发

2. memory/YYYY-MM-DD.md - 每日日志

记录当天发生的事件：

# 2026-02-23 工作日志

## 上午
- 08:00: 生成博客文章
- 09:30: 修复了 RSS feed 解析问题

## 下午
- 14:00: 与用户讨论新项目需求

## 学到的东西
- 使用 Chroma 存储向量比 Pinecone 更便宜

3. 自动记忆搜索

OpenClaw 在回答关于历史的问题时，会自动搜索 MEMORY.md 和 memory/*.md 文件：

// 当你问"上周我们做了什么？"
// OpenClaw 会自动执行：
memory_search(query: "上周做了什么")

代码示例与实现

示例 1：手动写入记忆

// 写入长期记忆
const memoryContent = `
## 新项目: Tech Blog
- 类型: 静态博客
- 技术栈: Node.js + 自动生成
- 创建于: ${new Date().toISOString()}
`;

await write({
  path: 'MEMORY.md',
  content: memoryContent,
  append: true  // 追加模式
});

示例 2：读取和更新记忆

// 读取现有记忆
const memory = await read({ path: 'MEMORY.md' });

// 更新特定部分
const updatedMemory = memory.replace(
  /上次同步: .*/,
  `上次同步: ${new Date().toISOString()}`
);

await write({
  path: 'MEMORY.md',
  content: updatedMemory
});

示例 3：使用向量数据库

# 使用 Chroma 存储记忆
import chromadb

client = chromadb.Client()
collection = client.create_collection("agent_memory")

# 添加记忆
collection.add(
    documents=["用户喜欢简洁的回答"],
    metadatas=[{"type": "preference", "date": "2026-02-23"}],
    ids=["pref_001"]
)

# 检索相关记忆
results = collection.query(
    query_texts=["用户偏好什么风格？"],
    n_results=3
)

示例 4：记忆压缩与摘要

当上下文过长时，智能体可以自动压缩：

// 总结长对话
const summary = await sessions_summary({

// 保存摘要到记忆

进阶技巧分享

1. 记忆分层策略

热数据（Hot）  → 内存缓存 → Redis
温数据（Warm） → 文件系统 → memory/*.md
冷数据（Cold）  → 向量数据库 → Chroma/Pinecone

2. 记忆衰减机制

不是所有记忆都值得永久保存：

# 基于重要性的记忆保留
def should_keep_memory(memory_item):
    importance_score = calculate_importance(memory_item)
    age_days = (now - memory_item.created_at).days
    
    # 重要性衰减公式
    retention_probability = importance_score * (0.9 ** age_days)
    
    return retention_probability > 0.3

3. 记忆冲突解决

当新记忆与旧记忆冲突时：

// 检查是否已存在相关记忆
const existing = await memory_search({
  query: "用户偏好编程语言"
});

if (existing.length > 0) {
  // 更新而非重复添加
  await memory_update({
    id: existing[0].id,
    content: "用户现在偏好 TypeScript（之前是 Python）"
  });
}

4. 隐私与安全

  • 敏感信息加密：API 密钥、密码不应明文存储
  • 访问控制：不同用户的数据隔离
  • 数据清理：定期清理过期记忆
// 安全的记忆存储
const sensitiveData = encrypt(userApiKey, encryptionKey);
await write({
  path: 'secrets.enc',
  content: sensitiveData
});

总结与下一步

重点回顾

✅ 记忆类型：工作记忆、短期记忆、长期记忆各有用途
✅ OpenClaw 内置：MEMORY.md 和 memory/*.md 提供开箱即用的记忆功能
✅ 向量数据库：适合大规模、语义化的记忆检索
✅ 分层策略：根据访问频率选择存储介质

实践建议

  1. 从简单开始：先用文件系统存储记忆
  2. 定期回顾：让智能体总结并更新 MEMORY.md
  3. 保持隐私：敏感信息加密存储
  4. 测试检索：确保重要记忆能被正确召回
